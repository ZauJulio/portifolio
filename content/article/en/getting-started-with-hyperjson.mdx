# Getting Started with HyperJson

This tutorial takes structured JSON — a project list, your skills, a playlist — from a loose
folder of files to a **validated, fully-typed** content type, with no backend and no runtime
cost. Use the sidebar on the left to jump between sections.

## Prerequisites

You need **Bun** (recommended) or Node ≥ 22, a Vite project, and a terminal. If you are starting
fresh, the Indago scaffolder gives you HyperJson already wired up:

## How HyperJson thinks #[concept/#0ea5e9]

HyperJson is **schema-first**. You describe a content type once as a `schema.json`; every JSON
file in that folder must satisfy it. At build time a Vite plugin validates the files (with Ajv)
and a codegen step turns the schema into **ambient TypeScript types**. So:

- invalid content **fails the build** — never your users;
- valid content arrives **fully typed** at every import — no hand-written interfaces;
- nothing runs at request time — it is all build-time.

## Define a schema

Create a folder for the content type with a `schema.json` describing one item:

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "additionalProperties": false,
  "required": ["name", "level"],
  "properties": {
    "name": { "type": "string" },
    "level": { "type": "integer", "minimum": 0, "maximum": 100 }
  }
}
```

## Add JSON content

Drop data files next to the schema (locale-aware folders work the same as HyperDown). Each file
is validated against the schema above:

```json
{ "name": "TypeScript", "level": 95 }
```

A typo like `"level": "95"` or an unknown property is caught at build time — with `strict`, unknown
properties are rejected; with `failOnError`, the build exits non-zero.

## Wire up the plugin

Add the validation plugin to your Vite config so the build validates + generates types:

```ts
import { hyperjsonValidationPlugin } from "@indago/hyper-json/plugins";

export default defineConfig({
  plugins: [hyperjsonValidationPlugin({ strict: true, failOnError: true })],
});
```

The codegen writes the generated types into your app's `.hyper-json/` tree — never edit those by
hand; they are regenerated every build.

## Query it with the hooks

HyperJson ships headless, in-memory helpers — **filter, sort, search, paginate, compose** — over
your already-typed JSON. No database, no async:

```ts
import { search, sortBy, paginate } from "@indago/hyper-json/hooks";

const matches = search(skills, "type", { fields: ["name"] });
const ranked = sortBy(matches, "level", "desc");
const page = paginate(ranked, { page: 1, pageSize: 10 });
```

## **HyperDown or HyperJson?**

This heading is **bold**, so the sidebar always keeps it expanded — it is the decision most
readers come for.

### Reach for HyperJson when…

…your content is **structured data** with a fixed shape: lists, records, config-like collections.
You want validation + types, not prose or full-text search.

### Reach for HyperDown when…

…your content is **prose** — articles, docs, recipes — that needs Markdown/MDX rendering and
SQLite full-text search. The two engines are independent; use either or both.
